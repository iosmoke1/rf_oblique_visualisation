# Визуализация деревьев решений, случайных лесов и oblique-разбиений

Проект представляет собой статическое веб-приложение для демонстрации работы нескольких моделей бинарной классификации:

- `Decision Tree`
- `Random Forest`
- `Oblique Decision Tree`
- `Oblique Random Forest`

Пользователь рисует чёрно-белое изображение на холсте размером 256 на 256 пикселей. После этого изображение преобразуется в датасет: каждый пиксель становится объектом с признаками `x`, `y` и меткой класса: `1` для пикселей рисунка и `0` для фона. Модели обучаются на доле полученных точек и затем строят собственное бинарное изображение по всей сетке холста

Сайт: https://iosmoke1.github.io/rf_oblique_visualisation/  
Репозиторий: https://github.com/iosmoke1/rf_oblique_visualisation

## Цель проекта

Цель проекта - визуально показать, как разные варианты деревьев решений аппроксимируют границу между двумя классами

Обычное решающее дерево использует разбиения вида `x < c` или `y < c`, поэтому его границы состоят из вертикальных и горизонтальных отрезков. Случайный лес обучает несколько деревьев на случайных подвыборках и усредняет их ответы. Oblique-деревья используют разбиения вида `a*x + b*y < c`, что позволяет строить наклонные границы и лучше описывать диагональные элементы рисунка

Приложение не требует backend-сервера и сборщика. Для локального запуска достаточно открыть файл: `index.html`

## Работа с интерфейсом

Основной сценарий использования:

1. Нарисовать бинарное изображение на холсте
2. Выбрать значения гиперпараметров
3. Нажать кнопку `Обучить модели`
4. Сравнить результаты моделей

Для каждой модели отображается итоговое изображение, построенное по предсказаниям модели, и набор метрик на train/test

## Гиперпараметры

- `Доля train`: доля данных, используемая для обучения
- `Макс. глубина`: максимальная глубина дерева
- `Минимум в листе`: минимальное число объектов в листовом узле
- `Bootstrap`: размер bootstrap-выборки для одного дерева в лесу
- `Количество деревьев`: число деревьев в случайном лесу
- `Направлений для oblique`: число направлений, проверяемых при поиске oblique-разбиения
- `Кисть`: толщина линии при рисовании

## Представление данных

Canvas считывается как массив пикселей. Для каждого пикселя формируется объект: `{ x: 0.42, y: 0.73, label: 1 }`

Координаты `x` и `y` нормируются в диапазон `[0, 1]`. Класс определяется по цвету пикселя: тёмные пиксели относятся к рисунку, светлые - к фону

Так как фон обычно занимает большую часть холста, перед обучением выполняется балансировка классов. Из положительного и отрицательного классов берётся сопоставимое число объектов, затем данные перемешиваются и делятся на train/test

## Модели

### Decision Tree

Решающее дерево строится рекурсивно. В каждом узле выбирается разбиение, которое сильнее всего уменьшает Gini impurity. Для обычного дерева проверяются условия:

```text
x < c
y < c
```

В листе хранится доля объектов положительного класса. При предсказании эта доля используется как `score`

### Random Forest

Случайный лес состоит из нескольких деревьев решений. Для каждого дерева формируется bootstrap-выборка из train-данных. Итоговый ответ леса считается как среднее значение `score` по всем деревьям:

```text
score = sum(tree_score) / tree_count
```

Такой подход снижает зависимость результата от отдельных неудачных разбиений

### Oblique Decision Tree

Oblique-дерево отличается способом выбора разбиения. Вместо проверки одной координаты используется линейная комбинация:

```text
a*x + b*y < c
```

Геометрически такое условие соответствует наклонной прямой. За счёт этого модель может компактнее описывать диагональные границы

### Oblique Random Forest

Oblique-лес использует те же bootstrap-выборки и усреднение, что и обычный случайный лес, но базовыми моделями являются oblique-деревья. В каждом дереве перебирается ограниченный набор направлений `(a, b)`

## Метрики

В интерфейсе используются метрики, которые напрямую связаны с бинарной классификацией пикселей:

- `accuracy`: доля правильных предсказаний
- `precision`: доля верно найденных пикселей рисунка среди всех пикселей, которые модель отнесла к рисунку
- `recall`: доля найденных пикселей рисунка среди всех настоящих пикселей рисунка
- `F-мера`: гармоническое среднее precision и recall
- `TP`, `TN`, `FP`, `FN`: элементы confusion matrix

Итоговая визуализация строится через порог `0.5`: если `score >= 0.5`, пиксель считается частью рисунка, иначе относится к фону

## Структура файлов

`index.html` - разметка интерфейса: панель настроек, холст пользователя, шаблон карточки модели и область результатов

`style.css` - стили приложения и адаптацию сетки интерфейса

`app.js` - связка DOM-элементов, обработчиков кнопок, обучения моделей, отрисовки результатов и вывода метрик

`src/drawing.js` - рисование на canvas, очистка холста и построение изображений по предсказаниям моделей

`src/dataset.js` - считывает пиксели canvas, формирует датасет, балансирует классы и делит данные на train/test

`src/tree.js` - классы `DecisionTree` и `RandomForest`, функции для Gini impurity, подбора порогов и выбора направлений

`src/metrics.js` - метрики классификации и confusion matrix

`model_demo.ipynb` - демонстрация обучения похожих моделей через `sklearn` и основные шаги работы с данными в Python

## Общий pipeline

1. `drawing.js` принимает пользовательский рисунок на canvas
2. `dataset.js` преобразует пиксели в набор объектов `(x, y, label)`
3. Данные балансируются и делятся на train/test
4. `app.js` создаёт четыре модели с выбранными гиперпараметрами
5. Модели обучаются на train
6. Для каждой точки сетки 256 на 256 считается предсказание моделей
7. `drawing.js` строит выходное изображение моделей
8. `metrics.js` считает качество на train/test-данных

## Jupyter Notebook

Файл `model_demo.ipynb` показывает разбор той же задачи в Python:

- создаётся бинарное изображение
- пиксели переводятся в таблицу признаков
- данные делятся `train_test_split`
- обучаются `DecisionTreeClassifier` и `RandomForestClassifier`
- oblique-идея работает через дополнительные признаки вида `a*x + b*y`
- строятся графики результатов и считаются метрики
